# Data model

`TownProject`, `HeritageFeature`, `SourceRecord`, `HistoricMapLayer`, `SettlementAgePolygon`, `ScoringMethodology`, and `ValidationResult` live in `src/domain/models.ts`. Dates are ranges with an explicit basis and confidence; a first-mapped date never becomes a construction date.

Publication uses one small declaration with four workflow states: `provisional`, `verified`, `publishable`, and `withheld`. A package must be explicitly `publishable`. Within it, a legacy record defaults to `verified` only when its existing `reviewed` flag is true; otherwise it is `provisional`. A verified record in a publishable package is delivered only when the runtime publication assessment finds no material provenance, licence, schema, or geometry blocker. Blockers resolve the effective state to `requires_review`; advisory warnings remain visible without blocking publication. Source data is retained in the package even when public/API/export projections withhold a record.

OSM-derived current-place records also use a claim-relative layer described in `CLAIM_EVIDENCE_POLICY.md`. `publication.profile` selects `mapped_context`, `verified_facility` or `editorial`; `claimEvidence` links an individual public claim to retained source records, its evidence tier, review date and optional expiry. `osmElement` preserves element identity, version, last-edit timestamp, changeset, visibility/status and check date when available. These declarations constrain public fields and do not replace the workflow state.
